# ابدأ من هنا

**المشروع جاهز كملفات وإرشادات، لكنه ليس مختبرًا تم تشغيله بعد.** لا توجد صور أو نتائج مصطنعة.

1. افتح `README.md` لفهم الفكرة، ثم `docs/setup-guide.md` للتنفيذ خطوة بخطوة.
2. تحقق من موارد جهازك. إذا كانت الذاكرة 8 GB، ابدأ بآلة Windows واحدة وتحليل السجلات محليًا؛ اترك تشغيل Wazuh إلى حين توفر الموارد.
3. استخدم شبكة VirtualBox داخلية معزولة. افصل اتصال NAT قبل أي تجربة.
4. ثبت Sysmon وفعّل سجلات Windows، ثم اختبر وصول حدث محلي قبل البحث عنه في Wazuh.
5. نفذ السيناريوهات واحدًا واحدًا. الأوامر تعليمية وغير مدمرة؛ فحص الشبكة محدود بأربع منافذ على آلتك الافتراضية فقط.
6. التقط الصور الحقيقية وفق `screenshots/README.md` واكتب استنتاجاتك بنفسك.
7. لا تكتب على LinkedIn أنك أنهيت المختبر قبل تشغيله والتحقق منه. يوجد وصف صادق مناسب للمرحلة الحالية في `docs/linkedin-project-description.md`.

## الرفع إلى GitHub

المستودع متاح الآن: [soc-home-lab](https://github.com/jojoxi0/soc-home-lab). استخدم الملفات الحالية القابلة للتصفح مباشرة. ملف ZIP الموجود في المستودع هو النسخة التحضيرية القديمة؛ حالة التنفيذ الفعلي للمختبر ما زالت قيد الإنجاز. التفاصيل في `docs/publish-to-github.md`.

## مصطلحات ضرورية

| المصطلح | المعنى البسيط |
| --- | --- |
| Event | سجل لما حدث على الجهاز |
| Alert | تنبيه ناتج عن قاعدة تفحص السجلات |
| Incident | حالة تستحق التحقيق أو الاستجابة بحسب الأدلة |
| False positive | تنبيه يبدو مهمًا لكنه ناتج عن نشاط سليم |
| SIEM | نظام يجمع السجلات ويساعد في البحث والتنبيه |
| Evidence | دليل حقيقي مثل سجل أو لقطة موثقة |

الأهم في المقابلة: اشرح كيف انتقل الحدث من Windows إلى Wazuh، ولماذا قد يكون التنبيه كاذبًا، وما الذي تؤكده الأدلة وما الذي لا تؤكده.
